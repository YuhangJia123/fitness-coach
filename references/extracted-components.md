# 来源 Skill 的提炼与改写

本文件记录当前项目从两个 GitHub skill 提炼的设计组件。它们只是参考来源；当前 `fitness-coach` 不复制其文件、动作库、接口、运行时或数据格式。

来源：

- [System Fitness Advisor](https://github.com/Reluctant2828/System-Fitness-Advisor-skill)
- [JayRHa/agent-skills 的 workout-planner](https://github.com/JayRHa/agent-skills/tree/main/workout-planner)

## 从 System Fitness Advisor 提炼

| 来源机制 | 当前项目的改写 | 不直接复用的部分 |
|---|---|---|
| 先识别意图，再从目标、时间、器械、记录、身体数据和未知项建立证据包 | 内部使用 `create`/`adjust` 两个入口，并将资料分成目标、条件、记录、身体、恢复、限制和未知项 | 不复制其完整路由枚举或 API 同步流程 |
| 区分已完成、计划、跳过和未知记录 | 使用项目内 `planned/completed/skipped/moved/unknown` 状态，只有 `completed` 才能证明进步 | 不把来源的默认状态或外部脚本当成项目事实 |
| 选择动作前先做安全门、同类训练比较和动作匹配 | 先筛查，再比较最近同类已完成训练，再选择精确动作或替代动作 | 不导入其 147 个动作数据库；当前只保留动作匹配规则 |
| 以“最小有用调整”和瓶颈为核心 | 每次修正先命名瓶颈：刺激不足、疲劳过高、技术不匹配、恢复不足、执行率低、器械不匹配、数据不足或安全问题，然后只改必要变量 | 不复制其机器可读 enum 或输出协议 |
| 现实重量规则 | 根据用户提供的器械刻度检查加重；不知道时标注假设，避免虚构小数机器重量或不可能的跳重 | 不把 20 kg 空杆、5 kg 机器刻度等默认值当作用户事实 |
| 目标模块分离 | 将力量举、增肌、减脂塑形、部位专攻和功能训练分成不同决策路径 | 不复制其模块文件和内部知识库 |

## 从 workout-planner 提炼

| 来源机制 | 当前项目的改写 | 适用场景 |
|---|---|---|
| 先收集主目标、经验、训练天数、单次时长、器械、限制和偏好 | 建立档案时只追问会改变计划的高影响字段，支持文字、截图、CSV、App 导出和历史日志 | 初次建立计划 |
| 按可训练天数选择分化 | 2-3 天默认考虑全身，4 天考虑上下肢，5 天考虑混合分化，6 天才考虑 PPL x2，并用恢复和偏好修正 | 增肌、一般力量、减脂塑形 |
| 复合动作覆盖主要动作模式，辅助动作解决弱点 | 先检查深蹲/膝主导、髋主导拉、水平推、水平拉、垂直推/拉、单侧和核心，再按目标添加辅助 | 器械受限或动作库不完整 |
| 每个动作选择一种明确的进阶方式 | 使用双进阶、线性加重、加组/加次数或 RPE/RIR 自调节，并说明触发条件 | 计划可执行和可复盘 |
| 预设热身、减量、恢复和日志 | 当前计划固定输出热身、停止线、减量条件和训练记录字段 | 所有训练目标 |

## 与本项目 PDF 原则的合并

- PDF 摘要提供专项性、超负荷、疲劳管理、SRA、变式、阶段增益和个体差异的训练理由。
- 两个来源提供输入整理、动作选择、现实约束、最小调整和可追踪进阶的工作流。
- 当前项目新增轻量视频资源检索层，只记录平台、标题、作者/账号、原站 URL、搜索词和可选互动数据；不能从动作计划或标题直接推断视频动作正确性。

## 当前项目的边界

- 数据只保存到项目内 `fitness-data/` 的 Markdown 文件，不接入外部数据库、Apple Watch、日历、云端健康 API 或第三方写回。
- 分析默认只读；用户明确要求建立或更新档案时才写文件，并保留历史版本。
- 数据不足时给保守起点或只问最少的高影响问题，不用模板填补缺失事实。
- 外部来源的许可证和项目条款仍然有效；本文件是设计提炼记录，不是对来源代码的再发布。
